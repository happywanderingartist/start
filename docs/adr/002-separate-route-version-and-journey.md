# ADR 002：分离 Route、RouteVersion 与 Journey

- 状态：Proposed
- 日期：2026-09-28
- 适用版本：Fan-route v0.3+

## 背景

公共路线会被编辑、纠错和重新算路；用户在现场可能删除、跳过或调整未完成地点；打卡和纪念又必须保留当时实际走过的版本。如果这些状态继续存放在同一个路线对象或全局 session 中，公共内容更新会污染用户进度，旧纪念也无法稳定回放。

## 决策

定义三类不同生命周期的对象：

- `Route`：公共路线身份、标题、偶像、城市和发布状态。
- `RouteVersion`：不可变的已发布快照，包含有序地点、证据引用、路段快照和计算状态。
- `Journey`：用户基于一个 `routeVersionId` 发起的一次复刻，包含用户调整后的地点顺序、跳过项、当前站、地图偏好和完成状态。

`CheckIn`、`JourneyPhoto` 和 `MemoryCard` 归属 Journey。`DollProfile` 归属用户，但 Journey 保存出发时的 `dollSnapshot`，避免后续换装改变旧记录。

## 核心不变量

- 已发布 `RouteVersion` 不原地修改；修正路线创建新版本。
- 已开始 Journey 固定引用出发时的版本，除非用户明确接受迁移。
- 用户调整只改变 Journey，不自动回写公共 Route。
- Journey 的已完成地点不能被移动到当前地点之后。
- 路段指标不可用时保存 `null + dataStatus`，禁止写入 0 或估算值冒充真实结果。
- 完成后的 MemoryCard 使用 Journey 快照生成，之后保持可回放。

## 结果

这会增加对象数量和迁移逻辑，但能明确区分内容、执行与记忆，也为未来路线共建、版本比较和失效提醒保留空间。

## 拒绝方案

- 复制一份 Route 到 localStorage：无法稳定处理版本更新、跨端同步和共建。
- 所有编辑直接修改公共 Route：会让个人临时选择污染公共内容。
- 只保存最终照片：无法解释用户实际完成了哪些地点和使用了哪个路线版本。
