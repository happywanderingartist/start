# Fan-route v0.3 Planning Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved v0.3 product architecture into independently testable vertical slices without discarding the verified v0.2 map foundation.

**Architecture:** Use a modular monolith organized by product capability. Preserve the existing RouteBundle and map Worker contracts, introduce RouteVersion and Journey boundaries before migrating screens, and deliver one end-to-end user outcome per implementation plan.

**Tech Stack:** React 19, TypeScript, Vite, Vitest, Testing Library, existing Worker API, localStorage/IndexedDB for the first web validation.

**Spec:** `docs/product/fan-route-v0.3-product-architecture.md` and `docs/product/fan-route-v0.3-core-flow.md`

## Global Constraints

- Tasks 1–6 map data and verified seed remain the source of truth; no fabricated POI or route metrics.
- Existing Task 7 changes stay unmerged until its App tests and full check pass.
- Migrate by vertical slice; do not perform a repository-wide directory move first.
- Route, RouteVersion and Journey are separate lifecycles.
- AI never publishes or confirms a POI.
- Companion and photo failures do not block route progress.
- Every implementation slice requires 390×844 browser verification and a separate review gate.

## Review Focus

- A published route changes while a Journey is active: the Journey continues on its pinned version.
- A route edit or recalculation fails: the draft and last successful Journey remain intact.
- Route metrics are unavailable: UI renders unavailable, never zero or invented estimates.
- External navigation returns without arrival: current stop does not advance automatically.
- Doll or media assets fail: CheckIn and Journey progress remain usable with truthful degradation.
