# Fan-route v0.3 产品架构

- 状态：Proposed
- 日期：2026-09-28
- 上游愿景：带着自己的娃，复刻可信的偶像足迹，并留下可收藏的追星旅程。

## 1. 核心价值与边界

Fan-route 解决的不是普通地图的 A 到 B，也不是泛旅行攻略。核心任务是让用户找到一条可信、可执行的偶像路线，理解地点为什么值得去，在真实世界中逐段完成，并把过程沉淀为个人追星记忆。

地图是基础服务；娃娃是陪伴层；AI 是搜索和内容生产的辅助层；社区是长期供给与治理层。任何一层都不能替代路线可信和现场执行闭环。

## 2. 三个产品循环

### 路线复刻循环

发现或搜索 → 判断可信度 → 查看并调整路线 → 开始 Journey → 逐站导航与到达 → 完成路线。

### 陪伴与记忆循环

选择一个娃 → 行程中获得动作反馈 → 到达后合影 → 完成后生成纪念卡 → 在足迹中回看 → 产生下一次出发动机。

### 内容供给循环

粉丝内容或投稿 → AI 提取候选 → 人工确认 POI 与证据 → 审核发布 RouteVersion → 用户纠错和失效反馈 → 新版本。

## 3. 产品领域

| 领域 | 核心对象 | v0.3 职责 |
| --- | --- | --- |
| Discovery | SearchQuery、SearchResult | 搜索已发布路线，提供诚实的结果、空状态和推荐 |
| Route Catalog | Route、RouteVersion、Place、SourceEvidence | 路线详情、地点证据、更新时间和数据状态 |
| Route Editor | JourneyDraft、RouteEdit | 排序、删除、跳过和受影响路段重算 |
| Journey | Journey、JourneyStop、NavigationPreference | 当前站、下一站、导航、到达、恢复和完成 |
| Check-in | CheckIn、JourneyPhoto、DollPlacement | 单点打卡、娃娃合影和照片保存 |
| Memories | MemoryCard、Footprint | 完成纪念、卡册和个人历史 |
| Companion | DollProfile、DollSnapshot、CharacterAsset | 单娃、轻量槽位、动作状态和身份锁定 |
| Contribution | RouteDraft、ReviewDecision、InvalidationReport | 内容生产、审核、纠错和版本发布 |

## 4. 信息架构

第一阶段一级导航为：

- 首页：娃娃入口、搜索、精选路线、最近旅程。
- 行程：即将开始、进行中和已完成的 Journey。
- 足迹：CheckIn、MemoryCard 和完成路线。
- 我的：娃娃、收藏、设置和内容贡献入口。

社区不占 v0.3 一级导航。路线进行中使用独立 Journey Shell，隐藏普通底栏，仅保留当前目标、导航、到达、调整和退出。

## 5. 页面架构

1. 首页：一句话表达目的地、偶像和时间偏好；当前版本只搜索已收录路线。
2. 搜索结果：展示匹配原因、城市、站点数、数据更新时间与可信状态。
3. 路线详情：路线故事、地点顺序、相邻路段和证据；进入调整或出发准备。
4. 路线调整：只编辑未完成地点；保存前预览变化，失败保留草稿。
5. 出发准备：选择地图、确认娃娃快照和必要提醒。
6. 路线进行中：明确当前目标和下一站，外部地图只导航当前路段。
7. 到达与打卡：标记到达、拍照、放置娃娃或稍后补记。
8. 路线完成：总结实际完成和跳过地点，生成纪念卡草稿。
9. 足迹详情：回看 Journey 快照、打卡和路线版本。

## 6. v0.3 范围

必须完成：诚实搜索、真实路线详情、路线调整、地图导航出口、Journey 进度恢复、单娃快照、单点打卡、完成页和最小足迹记录。

明确不做：公共社区信息流、评论、关注、物料交易、支付、实时位置共享、多娃商城、复杂 AI 抓取和无人审核发布。

## 7. 角色系统最小范围

v0.3 每个用户只有一个 DollProfile。脸、发型轮廓、头身比和材质身份固定；只开放少量服装、配饰和动作槽位。Journey 开始时保存 DollSnapshot，后续换装不修改旧 Journey。路线进行中只需要 idle、walk、arrived、photo 四个行为状态，不以完整动画系统阻塞路线闭环。

## 8. 数据真实性

- RouteVersion 的 Place 必须绑定确认后的 providerPoiId 和证据状态。
- 路段必须记录 provider、computedAt 和 dataStatus。
- 来源、故事、开放时间和入口未核验时明确显示未知，不使用营销文案掩盖。
- AI 输出永远是草稿；正式路线必须经过 POI 与证据确认。
- 页面不得把搜索匹配表述成 AI 已经理解或生成了路线。

## 9. 成功判定

v0.3 首先验证两件事：用户能否独立完成“搜索—判断可信—调整—导航—到达—恢复”的路线任务；娃娃与纪念是否让用户愿意打卡、保存或分享。两项分别记录，不用角色好感掩盖路线失败，也不用路线完成率替代陪伴价值验证。
