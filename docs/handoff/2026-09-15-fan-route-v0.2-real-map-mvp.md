# 星迹 v0.2 真实地图路线 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将当前“可点击但使用模拟路线数据”的手机网页，升级为高德真实 POI 与真实相邻路段数据驱动、可调整路线并能调起高德或百度导航的测试版 MVP。

**Architecture:** 继续使用 React/Vite 前端与现有 Worker。浏览器只调用本站 `/api`；Worker 保管高德 Web Service Key，负责 POI 搜索、POI 复核、相邻路段算路、缓存和错误归一化。产品内部统一使用 GCJ-02；高德作为唯一 POI/算路来源，高德和百度只作为当前站点的外部导航出口。路线内容、地图实体和用户进度分别建模，避免再次把展示文案、模拟数据和导航目标耦合在一个 JSON 中。

**Tech Stack:** React 19、TypeScript 5.9、React Router 7、Vite 6、Vitest、Testing Library、Node test runner、现有 Sites Worker、Amap Web Service API、高德 URI API、百度地图 URI API。

**Spec:** `docs/superpowers/specs/2026-09-15-fan-route-v0.2-real-map-mvp-design.md`

## Global Constraints

- 测试先行：每个行为先看到失败测试，再写最小实现，再运行完整回归。
- 前端代码和种子数据中不得出现高德 Web Service Key。
- 不使用虚构坐标、虚构距离或虚构时长作为降级结果。
- 产品内部坐标固定为 `gcj02`；百度 URI 必须显式携带 `coord_type=gcj02`。
- v0.2 只导航当前一个目的地；不承诺一次把完整多站路线导入第三方地图。
- 高德返回异常且缓存不可用时显示“暂时无法更新”，但仍允许使用已确认 POI 打开外部地图。
- 保留现有 `390 × 844` 手机页面主链路，不扩展社区、账号、AI 多模态解析或纪念卡生成。
- 路线中的 POI 只能来自用户明确确认的候选，不允许模型或关键词模糊匹配直接替用户确认实体地点。
- 当前上传快照没有 Git 历史。执行前先建立 v0.1 基线；此后每个任务独立提交，方便在面试中展示需求—实现—验证轨迹。
