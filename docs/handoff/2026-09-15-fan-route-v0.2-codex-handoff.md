## 1. 产品是什么

“星迹”是一款面向追星旅行和主题路线复刻场景的产品。它希望解决用户目前需要在小红书、地图 App 和聊天群之间反复切换的问题：

- 内容平台负责提供灵感，但地点分散、路线顺序不清晰；
- 用户需要在地图 App 中逐个搜索地点；
- 到达现场后还要重新查找拍照姿势、故事和打卡信息；
- 优质的小众路线难以沉淀、复刻和共同建设。

长期产品设想包括 AI 路线解析、用户共建、明星社区、单点打卡地、物料交换信息、路线完成小卡等。但这些不是当前 v0.2 的开发范围。

## 2. v0.2 只验证什么

本轮只验证一个核心假设：

> 用户能否在星迹中查看、调整并复刻一条真实路线，且不需要在内容平台和地图 App 之间反复整理、重新输入下一站。

v0.2 必须完成：

- 高德真实 POI 搜索和人工确认；
- 高德真实相邻路段距离、预计时长和交通方式；
- 路线换序、删除、跳过和添加已确认 POI；
- 调整后只重新计算受影响的相邻路段；
- 调起高德或百度导航到当前地点；
- 从地图返回后保留路线进度；
- 完成自动测试和真实地图验收条件；
- 为后续 5 名目标用户测试准备任务脚本。

v0.2 不做：

- 小红书抓取、图片 OCR、多模态 AI 路线解析；
- AI 自动决定某个关键词对应哪个 POI；
- 社区、关注、聊天、评论和公开发布；
- 登录、账号和跨设备同步；
- 实时位置共享、自动到站；
- 物料交易；
- 纪念小卡生成；
- 一次向所有地图 App 导入完整多站路线。

## 4. 当前已经完成的内容

### 产品侧

- 明确目标用户：追星人士，首批种子用户重点为安溥、苏打绿粉丝。
- 明确核心问题：路线内容、地图导航和现场打卡信息割裂。
- 确定先用手机网页验证，不先上架 App。
- 确定先从已有路线开始，不在首版实现完整 AI 解析。
- 确定高德为唯一 POI 与算路数据源，高德/百度为导航出口。
- 完成 v0.2 PRD、范围边界、接口方案、数据模型和验收标准。
- 完成测试先行的工程实施计划。

### 代码侧

v1 已有可运行主链路：

```text
首页 → 路线详情 → 路线进行中 → 地图导航模拟 → 返回继续 → 路线完成
```

已知技术栈：React、TypeScript、Vite、React Router、Vitest、Testing Library、Sites Worker。

已知 v1 状态：

- 首页任意非空输入会跳转到固定路线，属于模拟搜索；
- 安溥南京路线包含 5 个待核验地点；
- 距离和时长是原型估算，不是真实地图数据；
- “调整路线”仍是未开放提示；
- 高德/百度选择存在，但实际是站内导航模拟；
- localStorage 已保存路线进度和地图偏好；
- 现有自动测试、类型检查和 build 在交接快照中曾通过；
- 当前 GPT Work 中的上传快照不含原 Codex 仓库的 Git 历史，原 Codex 对话中的仓库状态才是执行时基准。

上述内容只代表交接时观察到的状态。Codex 必须在原仓库重新运行检查，不得直接沿用“已通过”的结论。

## 5. 关键架构决策

### 地图能力分三层

| 层级 | 责任 | v0.2 方案 |
|---|---|---|
| 数据计算层 | POI、距离、时间、交通方式 | 高德 Web Service API |
| 产品呈现层 | 路线卡片、路段、进度、调整 | 星迹自己的页面和状态 |
| 外部导航层 | 当前地点的实际导航 | 高德 URI、百度 URI |

### 坐标和数据责任

- 内部坐标统一使用 GCJ-02。
- 百度导航必须显式传递 `coord_type=gcj02`。
- 不使用未经地图服务商确认的坐标转换算法。
- 高德 Web Service Key 只保存在服务端环境变量 `AMAP_WEB_SERVICE_KEY`。
- 前端源码、种子 JSON、日志、错误消息和构建产物不得包含 Key。
- POI 只能由用户从高德候选结果中逐个确认。
- 地图失败且没有缓存时，不显示虚构数字，字段使用 unavailable/null 状态。

### 导航边界

星迹保存整条路线和进度，第三方地图只导航当前目的地。按钮必须显示具体目标，例如“导航到南京中国科举博物馆”，不能写成含义错误的“导航下一站”。

## 6. Codex 首次审查清单

开始编码前，请检查并汇报以下内容：

### 仓库与工程

- 当前目录是不是原 v1 仓库；
- 是否存在 `.git`、当前分支和未提交改动；
- 是否存在用户已有修改，不得覆盖；
- 包管理器、Node 版本、安装状态；
- `typecheck`、前端测试、Worker 测试和 build 的真实结果。

### 代码与需求差距

- 路线种子是否仍包含模拟字段；
- 页面有哪些地方依赖旧的数据结构；
- Worker 当前是否只提供静态资源；
- 地图导航是否仍进入模拟页；
- localStorage 状态是否可以复用；
- 实施计划中的文件路径是否与原仓库一致；
- 是否存在会导致 Task 1 无法独立完成的问题。

### 外部依赖

- 是否已配置 `AMAP_WEB_SERVICE_KEY`，只回答“已配置/未配置”，不得输出值；
- 当前部署环境能否保管 secret；
- 是否支持 Worker Cache API；
- 如果不支持，先提出低成本替代方案，不直接增加付费数据库。

## 7. 开发规则

1. 每次只执行一个 Task。
2. 行为测试先失败，再写最小实现，再运行回归。
3. 不为了让测试通过而降低 PRD 验收标准。
4. 不重写与当前 Task 无关的 UI，不扩展新功能。
5. 保留用户已有改动，不执行破坏性 Git 命令。
6. 每个 Task 完成后保持可运行、可构建、可回退。
7. 地图服务使用可注入的 fetch/cache，自动测试不请求真实网络。
8. 真实地图数据只在需要时通过环境变量调用，并留下核对证据。
9. 任何计划调整都写明：原因、影响范围、是否改变产品验收。
10. 未完成真实验收前，不把规划目标写成已经取得的成果。

## 8. 第一个执行任务

只执行实施计划中的：

> Task 1：建立可追溯的工程基线与统一测试入口。

Task 1 的目标不是开发地图功能，而是先建立可靠的工程验证基线，确保后续每个功能改动都能回答：改了什么、有没有破坏旧流程、是否可以稳定复现。

完成 Task 1 后必须暂停，不继续 Task 2。

## 9. 每个 Task 的强制验收门禁

完成代码不等于产品验收通过。每个 Task 完成后，Codex 必须暂停并从以下五层进行自审：

| 审查层 | 必须回答的问题 | 合格标准 |
|---|---|---|
| 需求符合度 | 实际做的是不是当前 Task | 对照 PRD 和 Task 验收项，无漏做、无擅自扩项 |
| 用户功能 | 目标用户能不能完成对应操作 | 实际页面主流程可用，加载、空状态和失败状态都有明确反馈 |
| 数据真实性 | 页面内容和计算结果是否可信 | 不使用模拟 POI、虚构距离或伪造结果；数据来源和时间可追溯 |
| 工程质量 | 是否破坏已有能力 | 新测试、旧测试、类型检查和生产构建全部通过 |
| 交付完整度 | 是否具备进入下一 Task 的条件 | 改动、风险、遗留问题和外部依赖都已说明，不存在阻塞项 |

### 9.1 验收结论

每个 Task 只能给出以下三种结论：

- **通过**：当前 Task 的验收项全部满足，可以申请进入下一项。
- **有条件通过**：核心目标已经完成，只存在不阻塞后续的小问题；必须登记问题、责任任务和处理时间。
- **不通过**：存在核心功能缺失、模拟数据冒充真实结果、回归失败或证据不足；继续修改当前 Task。

页面可以点击但没有验证证据，不算通过；自动测试通过但真实用户操作无法完成，也不算通过。

### 9.2 每次必须提交的证据

Codex 完成 Task 后必须提供：

1. 修改文件清单及修改原因；
2. 对照 Task 验收项的逐条结果；
3. 失败测试到通过测试的记录；
4. typecheck、完整测试和 build 的实际命令及结果；
5. 页面验证步骤、已知问题和是否建议进入下一 Task。

涉及地图能力时，必须分别说明：

- mock 测试是否通过；
- 真实高德接口是否已经验证；
- POI 是否经过产品负责人确认；
- 高德和百度是否在真实设备打开正确地点。

mock 测试通过不能表述为真实地图接入完成。

### 9.3 产品负责人复审

Codex 自审后不得自动进入下一 Task。产品负责人根据报告、页面截图或可运行版本进行第二轮审查，并给出：

- 通过，进入下一 Task；
- 有条件通过，登记问题后进入下一 Task；
- 不通过，返回当前 Task 修改。

产品负责人重点判断用户任务和 PRD 是否成立，不代替 Codex 审查代码实现细节。

### 9.4 Task 验收指令

每完成一个 Task，执行以下指令：

> 请暂停进入下一 Task，对当前 Task 进行验收审查。逐条对照 PRD、实施计划和交接文档，检查需求覆盖、实际功能、数据真实性、异常状态、回归测试和范围控制。请提供改动文件、测试命令及结果、页面验证步骤、遗留问题，并给出“通过／有条件通过／不通过”的建议。不要只依据测试通过下结论，也不要修改下一 Task 的代码。

## 12. 阶段完成定义

只有同时满足以下条件，v0.2 才能标记为完成：

- 5 个安溥南京 POI 经产品负责人逐一确认；
