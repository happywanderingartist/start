# START 后端分阶段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. 本计划由主代理逐项执行；不默认派生新代理。

**Goal:** 保留已完成目录基础，先验证真实数据库和微信身份接入条件，再打通地点投稿、审核、公共列表和社群共享数据。

**Architecture:** 模块化单体、PostgreSQL 主数据、私有媒体存储与地图 Provider Adapter。所有页面通过同一后台访问统一 ID；公共查询与私人写入权限分开，演示身份不能充当生产身份。

**Tech Stack:** 复用现有 Node.js、TypeScript、pg、Zod 和测试工具；云端为腾讯云候选，未决定具体套餐。无微服务、支付、物流、完整私信或交换完成认证。

**Spec:** 同目录 BACKEND_DECISIONS_DRAFT.md，2026-10-07 集中确认段为业务基线；BACKEND_GITHUB_RESEARCH.md 为已审阅参考。

## Global Constraints

- 所有新文件、数据库副本、证据和日志保存在 D 盘；不输出密钥。
- 现有 `.worktrees/start-slice-001`、旧原型与数据库受保护，不原地覆盖或重建。
- 工作分支在执行时通过 using-git-worktrees 创建；先检查当前附属工作区，避免重复创建。
- 首先核验已有 pg 与 SQL 迁移；不得直接采用演示种子替代真实用户数据。
- 小程序写入需真实服务端身份验证；手机号不强制；Web 跨端绑定后续接入。
- 每次地点投稿最多一个艺人，公共地点允许积累多个艺人关系；平台审核后公开。
- 物料归社区，可下架、申请、接受、自愿提供和撤回联系方式；不设置交换完成状态。
- 新页面先完成视觉审批，结构与 UI 优化使用 Interaction Design、Apple Design、Hallmark，视觉展示使用 Open Design。
- 本计划确认不等于云费用、公开部署、账号权限或未核定的数据保留期限获批。

## Review Focus

1. 迁移版本不一致或数据库恢复失败：停止写入，保留原数据与可恢复证据。
2. 伪造用户/管理员/社群身份：服务端拒绝，不能依赖前端按钮隐藏。
3. 重复提交与并发审核：只生成一次公共记录及通知，不覆盖他人贡献。
4. 查询缓存延迟：审核后的首页、社群和地图按同一 ID 展示一致数据。
5. 私有媒体或联系方式泄露：公共列表与分享序列化排除，撤回后服务端拒绝读取。

## 后续阶段与独立验收

以下为路线图，具体接口与代码级任务在阶段 0 结果明确后补齐，不将范围未知的事项直接投入实现。

| 1 身份与媒体 | 微信 code 在服务端换取身份、内部 userId、会话、私有照片存储与受控访问 | 真实真机登录；不强制手机号；伪造/过期身份拒绝；用户不能读取他人私有照片；密钥不进客户端或日志 |
