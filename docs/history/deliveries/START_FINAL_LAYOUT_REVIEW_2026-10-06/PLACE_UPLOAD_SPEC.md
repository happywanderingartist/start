# 用户上传地点 · 视觉批次待确认

范围：补齐用户贡献地点，而不是只有浏览官方或示例地点。一级架构不变；社区城市地点列表提供“上传地点”，地图提供“新增地点”，Me 提供“我的地点”。地点详情提供“补充照片 / 纠错”。首页仅推荐已公开地点，不增加新的一级入口。

## 流程与信息结构

登录 → 搜索现有地点或地图选点 → 填写资料 → 预览公开内容 → 提交 → 我的地点查看进度。登录前可浏览及准备资料，提交需要账号。选点允许手动搜索地址，拒绝 GPS 不阻断投稿。选中地图现有 POI 时复用其 ID 和坐标；附近同名地点提示“补充这个地点”，不强制创建重复记录。

必填：地点名、主分类、地址与确认位置。艺人单列为搜索、单选字段，每次投稿最多选择一位艺人，使用统一艺人库的 artistId，不接受将自由文字当作艺人身份。同一地点通过多次投稿积累多名艺人的标签，不因艺人不同重复建点。普通地点可不关联艺人，不要求推荐理由。主分类为餐厅、咖啡、娱乐、景点、书店、其他；兴趣为可选标签。照片建议添加，可无照片投稿；上传失败不得丢失文字或阻断草稿保存。营业时间、价格、链接为可选；未经核实不标注营业中。照片选择支持封面、删除、顺序调整，具体数量及文件大小由服务能力验收后确定。

艺人选择器：搜索、选择一位、替换、清除、确认；无匹配时提示换关键词，不能静默新建同名艺人。已选艺人保留到返回及草稿恢复。列表中的“艺人 A / B”仅为视觉占位，没有虚构实际打卡关系。

打卡同款独立于艺人字段：同一地点可新增多条记录，本次所有记录继承同一个已选 artistId，不提供记录级多选，分别填写作品/餐点/座位等同款内容、机位说明，并上传同款照片或机位参考图。机位允许没有艺人关联；照片不是全地点共用的模糊附件，而是绑定具体同款/机位记录。地点实拍、艺人同款参考、机位参考分别标明用途；参考图可附来源。更换艺人时先确认本次全部记录归属随之改变，不修改地点已有的其他艺人贡献。

审核公开后，社区城市地点列表、所属艺人社群地点列表及地图读取同一个 placeId 的已发布艺人关系和同款记录；地点只保留一份，多个艺人标签不生成多个重复地点。艺人社群只展示匹配该艺人的关系与记录，不能因投稿标签使用户自动加入社群。新增艺人关联及同款内容按贡献记录审核，不覆盖既有贡献；待审核资料不提前进入公共列表。

预览页明确公开字段（地点、照片、打卡同款、投稿昵称）及非公开字段（账号标识、草稿），提交前可返回修改。不公开投稿者的实时位置，不将设备 GPS 等同于地点坐标。地图用高德实际选点后接入；视觉示意不产生可导航坐标。

状态：草稿 → 提交中 → 待审核 → 已发布 / 需修改。审核为拟定规则，后端与运营尚未实现。重复点击提交禁用并使用幂等请求；失败保留草稿、说明原因并重试。需修改展示具体原因和重新提交入口；已发布地点才能进入公共城市列表、地图和首页推荐。草稿离开时提供保存或继续编辑；公开后的纠错保存修订记录，不覆盖他人贡献。

## 数据与实现顺序

PlaceSubmission 独立于公开 Place：authorId、cityId、name、category、tags、address、坐标系及经纬度、providerPlaceId、artistId（单值，普通地点可为空）、地点媒体引用、审核状态、反馈、版本与时间。公开地点另有发布 ID、数据来源及核验时间。PlaceArtist 为 placeId 与 artistId 的多对多关系，唯一约束避免重复标签；CheckinReference 记录 placeId、submissionId、artistId（继承投稿单值）、同款内容、作品、机位说明、带用途及来源的媒体引用、贡献者与审核状态。关系和同款记录均有独立 ID，可单独补充、修改和审核；公开标签仅来自有效已发布关系。审核通过生成或合并公开地点；投稿者修改自己的草稿，审核权限由服务端判断。

本批交付独立可编辑视觉 HTML、直接可看的 PNG 和此规范；不接入现有业务路由，不假装已上传。确认后先做本地流程（表单校验、草稿、重复提示、返回恢复），再接账号、媒体上传、真实地图、投稿与审核接口。完成需验证定位拒绝、无照片、上传失败、长地址、重复提交、六种宽度、键盘和返回恢复；真机及云端验收另外记录。
