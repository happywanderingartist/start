## 已确认的产品规则

Start / Community / Me 三入口；物料集市归社区；地点保留分类列表和地图。地点投稿不要求推荐理由；艺人单列为统一艺人库选择，一次投稿最多一位艺人；同一地点可积累不同艺人的贡献。同款、照片及机位归属具体投稿/记录，不能覆盖他人内容。首次选一个娃娃，日常不切角色，配饰暂缓。

## 已确认架构方向

采用一个模块化后端服务和一套 PostgreSQL 主数据，拆清账号、地点投稿、社群、演出、物料、行程打卡和 Book 模块；照片用文件存储，地图能力用已有高德接口。Web、小程序和管理后台访问同一套领域服务与 ID；后台审核是独立管理界面，不是数据库控制台。云端选择待账号、成本与兼容性核验，CloudBase PG 为候选，不能假设环境已开通。

用户系统保留内部 userId；微信身份以 AppID + OpenID 绑定，不凭昵称合并账号。已确认第一版先完成微信小程序登录，Web 跨端绑定后续接入，不能以模拟身份代替真实登录验收。未登录可浏览已公开内容，投稿、加入社群、交换申请、收藏与打卡需登录。微信身份即可使用，手机号不强制绑定，不能因未绑定手机号阻止投稿、加入社群、交换或打卡。

公开地点使用 placeId，投稿使用 submissionId，艺人关系和同款有独立记录 ID。审核通过才追加到公共地点，投稿者不能自行写“已审核”；同城列表、艺人社群和地图以同一公开数据查询。重复地点先按地图提供方 ID 匹配，同名近邻供人工核对，不仅凭名称自动合并。新增内容与修订分开，保留来源、贡献者和审核记录。

演出使用 eventId、参演 artistId 关系及场地 placeId；日期与取消状态统一维护。本周列表来自时间窗口查询，不复制演出。时间计算保留场地时区，第一版中国大陆显示用北京时间。艺人库和演出资料由平台维护；用户可提交补充/纠错，由平台审核后应用，不直接修改公共记录。来源与改期核验责任归平台，具体资料来源仍待确定。

社群由用户申请、平台审批后创建。申请使用 communityApplicationId，保存申请者、主题/关联艺人或城市、名称、简介及审核结果；批准后生成 communityId，申请重复提交需幂等。申请者获批后作为本社群管理员，可管理简介、公告和成员；其他内容向平台申请修改。权限仅限其管理的 communityId，不具有公共地点、艺人、演出或平台投稿的审批权；成员管理不授予修改成员账号、私人 Book 或联系方式的权限。管理员转让与社群解散由管理员提交申请、平台处理，不直接删除成员个人记录。批准、拒绝或要求补充均有明确反馈，拒绝保留理由。

物料使用 listingId，关联活动、艺人及可选集合地点；交换申请以 exchangeRequestId 独立保存。用户已确认线下申请与接受、不含支付；平台只管理发布、申请和接受，不记录或认证线下是否交换完成，不设置双方或发布者的完成确认流程。接受申请不代表已完成交换，不据此结算物料库存或转移所有权。申请被接受后双方可自愿提供联系方式。不自动公开账号手机号或微信号，不要求双方对等披露。联系方式绑定具体 exchangeRequestId，仅该交换双方可按服务端权限读取；发布物料、接受申请或填写联系方式不能使其公开到列表、帖子或分享页面。已确认联系方式可随时撤回；自动保留期限仍待确定，不能依赖平台未记录的交换完成时间。

打卡记录使用 checkinId，关联用户、地点和可选行程；用户已确认自由打卡，不进行现场验证，不区分所谓验证到场与补记资格。精确位置不作为默认公开字段；打卡不采集用于到场验证的精确位置。打卡及 START Book 的照片、票根默认仅自己可见，主动分享才公开用户选中的内容；分享不能暴露其余卡册、私人字段或交换联系方式。票根和 Book 引用完成记录并保留当时快照，公共地点修订不能随意改变用户历史纪念内容。已确认分享可撤回，提供注销入口并删除私人记录和联系方式；分享目的地、链接有效期、公开投稿、审核日志及备份的具体保留期限仍需明确。

权限由服务端强制执行，前端隐藏按钮不等于权限。普通用户只编辑自己的草稿与个人记录；公共已发布内容通过修订/审核更新。管理员操作留审计记录；社群管理员仅管理本社群简介、公告与成员，其他内容提交平台审批。审核、加入社群、交换等关键写入有事务、唯一约束和幂等；统一刷新相关查询缓存，避免多页面状态不一致。

## 本轮已确认的三个决定

1. 投稿审批：平台管理员审批后公开。社群管理员暂不具备审批权限；被退回的投稿可修改后重新提交。
2. 打卡：允许自由打卡，不验证位置，不要求 GPS 授权；记录用户、地点、打卡时间及可选照片/文字，不标记为已验证到场。定位用于附近推荐和导航，不作为打卡门槛。允许补记过去日期和重复打卡，每条独立保存，默认私密。
3. 物料：线下交换，支持申请与接受，不含支付。平台不管理或认证交换是否完成，不设完成确认流程。第一版不引入买卖、邮寄和完整私信系统；集合信息仍待确认。

以上三项已由用户明确选择，不能用早期建议替代。第二轮已确认：艺人与演出由平台维护，用户可提交补充/纠错；社群由用户申请、平台审批。第三轮已确认：手机号不强制；打卡与 Book 默认仅自己可见，主动分享所选内容；交换申请被接受后双方自愿提供联系方式。第四轮社群管理员范围已确认：管理简介、公告和成员，其他内容向平台申请修改。第五轮已确认：交换是否完成由用户线下自行处理，平台不管理或认证，取代此前待选的双方确认或发布者单方确认方案。后续集中确认结果见下一节；尚未明确的保留期限、部署地域、预算、备份与上线配置继续单独核定。
