# START 后续任务工作规则

来源：用户 2026-10-16 明确要求，适用于后续产品、界面和工程任务。

1. 先读取与任务真正相关的成熟 skill，记录名称、来源路径及本批应用的原则；不能仅列名称而不读内容。
2. 核对现有代码、已确认设计、测试证据和未完成项；已实现接口与已接通界面分别记录。
3. 实现前搜索成熟 GitHub 项目，记录可复用优势、局限、维护及许可证证据；无法核实的项目指标明确标为未核实，不以星标代替质量。
4. 先输出范围、结构、交互状态、数据权限和验收文档，再交用户确认。本批确认不代表后续批次获批。
5. 新视觉先使用 Open Design 制作或展示可编辑稿，并提供可直接查看的图片；连接不可用时如实记录，不将本地页面称为 Open Design 成品。视觉以已确认首页、Apple Music 底座、组合色卡、原 Logo 和角色资产为准。
6. 确认后按文档逐项开发；常规授权内的读取、修复、测试无需重复询问权限。正式账号、云部署、费用和新范围单独处理。
7. 用接口、浏览器、六宽度及权限测试验收，记录失败，不用浏览器模拟替代真机、真实身份或 GPS 验收。

默认由当前会话执行，不额外启动新对话或并行代理。每批结束更新已完成、未完成及下一批文档；所有产物保存在现有 D 盘项目。
