# START 艺人 × 城市打卡地点与独立路线 · 2026-10-07

用户最新澄清为本批依据：主体是某艺人在某城市的打卡地点集合，可按类型细分浏览，并不要求形成路线。路线独立存在，由用户有意编排。此记录替代此前“下一批只做路线编排”的优先级，不改变既有投稿审批或视觉确认关卡。当前仅修订结构，未实现页面和数据库接口。

## 主要浏览流程

搜索艺人 → 进入艺人页，默认显示所有城市，顶部为独立路线，下面为全部公开关联打卡地点 → 选择城市同步筛选路线与地点 → 按类别细分地点 → 列表或地图查看 → 单个地点详情。同一艺人在不同城市有独立结果集，切换城市刷新地点与地图；返回保留原艺人、城市、分类、视图、滚动位置及已选地点。浏览不要求加入社群，加入和内容查询是两种独立状态。

示例：苏打绿 → 北京 → 全部 / 美食 / 咖啡 / 景点 / 娱乐 / 书店；切换台北显示台北地点。艺人搜索结果不直接跳入路线，城市页没有路线仍可正常展示地点。城市候选来源为该艺人公开关联地点或公开路线所覆盖的城市；某城市只有路线、无独立艺人打卡关系时，要明确地点为空，不由路线主题凭空推断艺人到访。

一级分类支持用户要求的美食、咖啡、景点等；美食可继续按餐厅、小吃、甜品等细分。界面采用一级分类栏与选中后出现的子分类，避免全屏堆标签；现有餐厅等分类字段需要在实现阶段明确映射，不能直接丢弃或批量改写旧分类。照片、同款内容、作品/机位标签归地点的具体贡献记录，不将作品时间点当作路线顺序。

地点列表以照片、地点名、类型与同款标签为主要信息，不强制写推荐理由。地点地图仅显示当前筛选结果：艺人 AND 城市 AND 选中分类；选中标记联动对应列表项，选中列表项定位地图。无结果显示该分类暂无打卡点，可清除分类或投稿，不能回退到其他艺人的普通POI并称为同款。

## 地点与路线分开

艺人概览和城市结果采用“路线在上、地点在下”，两类内容分开维护，不再要求通过两个独立标签页切换。地点集合没有起点、终点、序号、全程耗时，也不绘制连接线。没有路线时只显示暂无路线，不影响地点可见。路线内容才有站点顺序、分段、交通方式、路线轨迹和规划耗时；可引用既有地点，但它是另一份内容。

参考整理：苏打绿北京/台北资料先进入无序的艺人城市地点参考集合，作品时间点和地区分组保留；其中真正编排过的行程另建路线。安溥济南/南京的明确顺序保留为路线参考，同时逐点核对艺人关联、城市、位置和来源；不因为列在主题路线中就自动确认所有地点为艺人实际到访点。上海地图标签待具体名称/位置/顺序核对。原图中跨城资料分配到实际所属城市，不硬塞北京或台北。

## 投稿与数据联通

投稿入口保留“上传地点”和“上传路线”。上传地点：一次选一位艺人，选择城市和实际地点，填写类型、同款、照片/机位和来源 → 平台审核 → 对应艺人城市地点集合可见。不要求先建立路线，也不自动新建一条单站路线。上传路线：选择主题艺人/城市，添加地点并编排 → 审核后在路线内容中显示。单艺人路线限制、最少站数等仍是待本批确认的提案，不因本次澄清视作获批。

Place以placeId保存唯一地点；PlaceArtist/贡献记录保存经审批的艺人关联及同款内容；艺人城市地点集合按公开贡献和地点城市过滤，由查询实时产生，不需要用户重复上传“整个集合”。一个地点可关联多个艺人、被多条路线复用；各艺人页只显示自己的同款贡献。Route拥有独立routeId及有序RouteStop(placeId)，路线主题艺人不会自动写入PlaceArtist。未审核路线、地点和同款不会进入公共查询。实现时对审批发布/撤回、城市/分类修订统一刷新列表、地图及相关页面的查询缓存。

每项公开内容保存来源与更新时间；图片里的历史关闭/拆除描述需复核。没有真实规划数据的路线段保持不可用，地点集合不需要任何路线距离。单点打卡沿用已确认的自由打卡，不强制GPS或完成路线；个人打卡和Book默认私密。

## 本批设计优先级

先用Interaction Design、Apple Design、Hallmark制作艺人搜索/艺人页、城市切换、分类地点列表与筛选地图；同步明确上传地点/路线入口。再制作路线编辑与详情，主次清晰、沿用首页Logo和组合色卡。新视觉稿交用户确认后才接业务代码。Open Design恢复可达后用于可编辑展示；前轮服务不可达状态不作为“已成功使用”。

验收重点：同一艺人切城、同城切艺人、一级/子分类叠加、筛选列表与地图一致、无路线仍有地点、无地点但有主题路线不捏造艺人关联、待审核不可见、多艺人同地点只显示对应同款、返回恢复、投稿发布后多处同步、六宽度与键盘操作。

## 首页推荐规则 · 用户补充确认（2026-10-07）

首页以用户当前定位城市为优先范围，再结合兴趣推荐活动、地点、路线、演出及打卡点。上海用户优先看到上海内容。兴趣不只来源于关注/加入的艺人社群，还包括用户选择的音乐风格、内容类别与偏好，例如流行音乐相关酒吧、Livehouse、唱片或主题店铺、演出及相关打卡点；上述是内容类型示例，不是已验证店铺名单。

推荐逻辑分开判断：当前/手动选定城市的匹配度、兴趣风格匹配、关注艺人关联、活动日期与当前有效状态、内容核验与质量。音乐类型与地点/活动主题使用有来源且经审核的标签；用户关注艺人可以辅助兴趣判断，但不直接断言用户只喜欢该艺人的风格，也不把播放过音乐的普通店铺自动标成流行音乐主题店。演出保留已确认的平台维护及用户纠错审批机制。

定位获准后用于确定城市，拒绝定位仍可手动选城。外地内容可以作为后续发现内容，但不挤掉本城推荐；本城某类无匹配不伪造结果、不自动改城。首次使用可依据用户显式选择的兴趣和城市，未形成兴趣时提供城市公开内容并让用户逐步选择。

界面沿用紧凑滚动推荐卡片与现有地点列表，避免因推荐增加而重新放大卡片；活动、地点、路线、演出标明类型、城市，按内容需要展示时间/地址等必要信息。不增加用户此前拒绝的推荐理由文案。精确距离仅在获得必要坐标且真实计算后显示。个性化信号、排序及跨页面查询目前尚未实际接入；本轮只确认需求，不变更视觉或后端。

用户确认一个艺人一个社群，城市仅作为社群内内容筛选。加入该唯一艺人社群可影响兴趣推荐，不要求加入才允许浏览艺人地点/路线。物料状态由发布者自选，平台不追踪、确认或干涉交换完成；演出变更不提醒物料发布者，不自动改变物料状态或交换集合安排。此决定覆盖COMMUNITY_EVENT_LINKAGE.md中的原建议，未执行业务代码或数据迁移。
